# 反面教训

写之前扫一遍，验证时再扫一遍。每条都是真踩过的。

## 结构与叙事

1. **模板优先而非内容优先**：拿着固定模板塞内容，会让不合适的 section 变成累赘、合适的内容没地方放。
2. **过度规定叙事模板**：每份材料的阅读路径不同，不要把某一次改稿的结构写成通用结构。
3. **把长文切成卡片墙**：卡片适合承载补充细节，不适合取代连续正文。读者还没 get 到脉络时，不要让他到处点卡片找主线。
4. **一屏糊太多信息**：违反渐进式披露，第一屏应该 30 秒看懂骨架。
5. **关键论证藏在折叠里**：把所有可展开区收起后主线断掉，说明折叠区被当承重墙用了。
6. **末尾加总结章**：读者刚读完，不需要复述。结尾只能是前文没安放过的新判断。
7. **论文当综述写**：目标是帮读者快速 get 方法，不是综述 20 篇 related work。只挑形成对比的少数方案。
8. **综述当论文列表写**：综述的价值是梳理关系和脉络，不是堆引用。重点论文要递归做深度展开（图 + 方法讲解 + 示例），只给一句话摘要等于浪费综述的结构。
9. **综述不分类就铺开**：没有 taxonomy / 分支导航就直接列论文，读者会迷失在几十篇工作里。先给全景分类，再按分支展开。
10. **综述全部展开**：引用 30 篇论文全部深度展开会淹没读者。默认折叠，按需探索；超过 15 篇重点论文时先与用户确认范围。
11. **综述论文用 h3 平铺而非折叠卡片**：全部平铺会让页面变成无法导航的长卷。这是综述最常见的退化模式。
12. **项目页退化成目录树导览**：一节讲一个目录、每个文件配一句「负责 xxx」。这是文件清单不是解读。section 由读者的疑问决定，不由目录结构决定。
13. **复述 README**：README 已经存在，读者可以自己看。页面的价值在 README 没写的那部分——为什么这么设计、什么情况下会失效。
14. **页面长度不匹配材料信息量**：几百行的小工具硬撑成六节，只会稀释。该三节就三节。

## 术语与读者

15. **没有读者画像就开始写**：不知道读者已经懂什么，会同时造成常见术语解释过度、材料专属术语解释不足。
16. **把相邻概念压成同一个词**：原文区分 function、artifact、runtime output，就不能全部翻成「上下文」。先定术语表，再写正文。
17. **先抛术语、后讲机制**：读者看到 `(1+1)-ES`、crossover 等名称，却不知道实际发生了什么。先讲每轮做了什么，再给术语名称。
18. **类比已有概念却不讲边界**：说「A 可以理解为 harness」还不够，必须说明 A 是完整 harness、其中一个子系统，还是仅在某个实验接口下相似。
19. **用无关领域案例解释系统论文**：随意使用法律、医学等案例会引入额外认知负担。优先使用原例，或 coding agent、evaluation harness 等目标读者熟悉的场景。
20. **train / validation 数据流含糊**：只写「验证集选择更好的方案」会隐藏候选如何产生、是否冻结、验证信息是否回流、最终保留什么。必须逐项交代。
21. **替作者编造设计理由**：代码里没写为什么、文档也没说时，宁可写「文档未说明原因」，也不要编一个听起来合理的理由——读者会当真。
22. **整页堆英文**：面向中文读者的页面，正文/导航/按钮一律中文。只有专有名词、代码、需要原味的金句可以保留英文。

## 图

23. **有好图不用**：原文的 pipeline 图比自己重画的更准确、更可信，务必优先复用。
24. **主图被压糊**：给宽流程图设过小的 `max-height`，或硬塞低分辨率原图，都会让方法主图变成糊图。原图读不清时改用清晰 SVG 主图，把原图放折叠区核对。
25. **画错流程图**：流程图必须忠于原文真实依赖。图如果让逻辑更难懂，就删掉或改回文字。
26. **图片说明敷衍**：只写一句「如图所示」等于没写。读者需要知道图里每个关键模块在干嘛。
27. **用 ar5iv 图片 URL**：ar5iv 不对外暴露静态图片文件，请求会 redirect 到摘要页，导致所有 `<img>` 空白。必须用 `arxiv.org/html/<id>v<ver>/<file>.png` 并 `curl -sI` 验证 200。
28. **关键对照只给一句话**：选作本文动机或方法的关键对照，却不配图、不讲 method，读者无法理解它为什么重要。顺带引用则保持一句定位和链接。
29. **为动画而动画**：内容本身是并列关系时，硬做时序动画反而混淆结构。
30. **搬运实验表格**：大段数字堆砌读者不会看。单篇精读只给最核心结论；综述里用一句话定性描述有效性即可。

## 代码与交互

31. **中文双引号混 ASCII 双引号**：`"把"重点"加粗"` 让 JS 直接 parse 失败，页面看起来是静态的。必须 grep 扫一遍。
32. **可展开卡片的点击绑在容器上**：点击卡片内部任何子元素都会冒泡触发收起。点击只绑头部，或用事件委托 + `stopPropagation`。
33. **贴样板代码**：import 块、`__init__` 赋值、CLI 参数定义占篇幅但不承载信息。
34. **色彩 / 装饰过载**：渐变背景 + 霓虹色 + 多色 accent + 发光阴影叠在一起，读者注意力被视觉抢走。色用得越少，信息越突出。
35. **accent 色直接当正文色**：暖赭色系的 accent 对浅背景通常不到 4.5:1，用于文字会不合规且难读。文字用加深版本。
36. **丢掉原文里的具体示例**：input-output 样例、case study、running example 是帮读者「真的理解」的最佳素材。但超过 5 行的要默认折叠——保留 ≠ 平铺。

## 文风

37. **skill 工作词汇泄漏进页面**：「读者画像」「主线」「承重墙」是这套流程的内部语言，读者没读过这套 skill。真实案例：把一个项目的 SKILL.md 在架构图里标成「Skill 契约与参考规则」，原材料从没这么叫过。页面名词只有两个来源：材料本身，或读者的行业通用词。
38. **标题全是格言句**：每个 h2/h3 都写成「A 不等于 B」「先 A 再 B」式判断句，连读像语录合集，一眼 AI。判断句是重音，一页至多两三个，同一句式不重复；其余标题用「材料专属名词 + 事实」的平实短语。
39. **为标题发明抽象名词**：「事实容器」「过程纪律」「模板偏差」这类词材料里根本没有，读者要停下来猜它指什么。标题用材料里的文件名、模块名、阶段名、数字。

## 验证

40. **只做静态检查不开浏览器**：Lint 过不代表 JS 能跑，必须看 Console。
41. **只验证交互的默认状态**：默认页正常不代表展开后正常。最长的 tab、步骤和说明卡必须分别在桌面与窄屏检查，防止固定高度裁切内容。
42. **把浏览器缓存当成当前版本**：改完重新打开要加 `?v=<timestamp>`。
43. **谎报验证结果**：没跑成的检查如实说没跑成，不要含糊带过。
