# 接住输入

四种输入形态，做法各不相同。先判断拿到的是哪一种，再选对应做法——不要不分场景地一律"读一遍全文再说"。

## 本地文件

- **md / txt / 源码**：直接读。文件不大的话读全文；源码文件按需读，别把整个仓库当成一个文件囫囵吞。
- **pdf**：不要自己解析，用 pdf skill 提取文本和结构。

## 本地文件夹（项目 / 代码仓库）

**先摸结构，再读细节。不做全文通读。** 目标是能一句话复述"这个项目在干什么"，而不是记住每一行实现。

摸结构的顺序：

1. **README** —— 项目自己怎么介绍自己
2. **目录树** —— 模块怎么划分，哪些是核心、哪些是辅助
3. **入口文件** —— 程序从哪里开始跑（`main.*`、`index.*`、`cli.*` 之类）
4. **配置文件** —— 依赖了什么、怎么跑起来（`package.json`、`pyproject.toml`、`Makefile` 之类）

摸完这四层再决定要不要往下深挖某个具体模块——只挖大纲里真正需要讲清楚的那部分，不是挖到底。

## URL

抓正文，不是抓整张网页的所有 DOM。arXiv 论文不要抓 PDF 页或摘要页，用 HTML 版本：

```
https://arxiv.org/html/<id>v<ver>/
```

## 对话内容

如果用户要求把"当前这轮对话已经聊出来的结论"做成可视化页面，**直接使用对话里已经产出的结论，不要重新检索或重新分析**。这一步的输入就是对话本身。

## 图片

组图的核心原则：**动手画图前先找现成的图**。原作者、原仓库、原论文大概率已经画过架构图、流程图——先找,只有找不到合适的、或者找到的图在正文宽度下看不清,才轮到自己画 SVG。

### 取图来源与优先级

1. 本地资源目录
2. md 文件里引用的图片
3. 网页正文里的 `<img>`
4. arXiv 的 HTML 版本页面

### 扫描目录清单

在本地文件夹场景下，按这个清单找图（不止 assets，逐个扫）：

```
assets/  images/  img/  figures/  docs/  static/
```

### 禁止使用 ar5iv

**不要用 `ar5iv.org` 取 arXiv 论文的图。** ar5iv 不对外暴露静态图片文件，直接请求图片路径会被重定向到论文摘要页，结果是页面里所有 `<img>` 全部变成 404。取 arXiv 图片一律走 `arxiv.org/html/<id>v<ver>/` 这条路径。

### 远程图必须校验

凡是要引用的远程图片，先验证再使用：

```bash
curl -sI "<图片 URL>"
```

确认返回 `HTTP 200` 且 `content-type` 是 `image/*`。校验不过的图不要往 body 里塞——`build.sh` 里的 `inline_images.py` 虽然下载失败会保留原引用而不中断构建，但那样产物里会留下一张实际打不开的图，不如提前筛掉。

### 收图标准

**收**：架构图、流程图、示意图，以及能一眼说明这项工作核心创新点的图。

**不收**：

- 实验结果的柱状图 / 折线图截图
- prompt 模板截图
- ablation（消融实验）图表
- 纯数据表格截图

这类图对外行读者没有解释力，塞进去只是凑数,不放。

### 数量与自制

- 每个主题最多用 1–2 张图，不要为了"看起来丰富"堆图。
- 原图信息量够、但在正文宽度下缩得太小看不清时：自己画一张清晰的 SVG 当正文里的主图，原图放进 @assets/components.md 里的「图片与折叠说明」组件（`<figure>` + `.fig-toggle`）,触发文案默认是「展开说明 ▸」，这种场景下可以按需把文案改成「查看原图 ▸」，保留出处但不占主线阅读空间。
- **只有在找不到合适的现成图时才自己画 SVG，不为凑图而凑图。** 有些主题就是没有一张图能讲清楚，那就不放图,用文字和类比讲。

### 图片会被自动压缩转码

`build.sh` 里的 `inline_images.py` 在内联图片时会按三条硬编码阈值处理，写 body 前要知道这些行为，免得构建完发现图变了样却查不到原因：

- **宽度超过 1600px** 的图会被等比缩放到 1600px。
- **体积超过 300KB 且不含 alpha 通道**的图会被**静默转码成 JPEG（quality 80）**。这一步有损——图里如果有小字标注（比如密密麻麻的架构图标签），压缩后可能糊掉。
- **全部图片内联后总体积超过 5MB** 会打印告警并列出体积最大的 5 张，但不会中断构建。

因此：细节要紧的图（带小字标注的架构图、需要放大看的示意图）本身就该控制在 300KB 以内，或者优先用 SVG——SVG 是矢量格式，不受这三条阈值影响，不会被缩放也不会被转码。
