# 综述专项（Survey / Review）

## 什么时候走这条

标题含 survey / review / overview / tutorial，或正文结构以分类梳理多篇工作为主、没有提出自己的新方法。

这条**替代 @references/paper.md 的叙事主线**；SKILL.md 的通用流程、@references/ingest.md 的图片规范、@references/visual-patterns.md 的视觉规范仍然适用。

## 叙事主线

```text
这个领域要解决什么问题
→ 综述的分类框架（taxonomy）
→ 按分支递归展开每篇关键论文
→ 跨方法对比与趋势
→ 开放问题 / 未来方向
```

### 1. 领域全景（轻量）

用 2–3 段白话说清「这个领域在做什么、为什么重要」。综述给了 taxonomy 图 / 分类树的，**优先引用原图并配中文说明**。没有原图时自制一张分类树或 mindmap，让读者一眼看到全貌。

### 2. 分类框架（核心骨架）

- 把综述的分类维度提炼成**可折叠的树形导航**或**分栏 tab**，读者能按分支逐个探索
- 每个分支 / 类别给一段概述：这类方法要解决的是什么问题；多篇论文之间有明显继承关系的，捋顺解决方案的发展

### 3. 问题解耦（每个分支必做）

每个分支在展开具体论文之前，必须先用 1–2 段话定义这个方向的**核心矛盾**和**子问题拆解**：

```text
先明确：这个方向到底要解决什么问题？
再映射：每篇论文在这个问题上做出了什么改进？
最后组织：按子问题分组，而非按论文发表时间排列
```

论文按其主要解决的子问题分组呈现，**而非按时间线或引用顺序平铺**。目的是让读者先理解问题结构，再看具体解法——避免论文堆砌、变成孤立的卡片列表。

### 4. 递归展开关键论文（重头戏）

对综述中重点讨论的每篇论文，**按照单篇论文叙事主线的深度去生成内容**：

- 问题动机（一两句话）
- 核心方法的 pipeline / 架构图（优先从原论文取图，见下方「递归取图策略」）
- 方法讲解：输入什么 → 怎么处理 → 输出什么，让没读过原文的人也能转述
- 动画：示例动画能更好表现流程时优先用动画，示例优先选自原文 case
- 关键实验结论：围绕论文 motivation 和这一块的核心问题来写。到底有哪些贡献？多大程度上解决了这个领域问题？**用一句话定性描述有效性即可，不堆 benchmark 数字**

**呈现形式：可展开的深度卡片。** 折叠态显示论文标题 + venue + 年份 + 一句话核心描述（小字灰色，通俗易懂），让读者不展开也能判断是否值得细读；展开后是完整的方法解读（图 + 文字 + 示例）。

**禁止用 h3/h4 标题直接平铺展开论文内容**——综述引用量大，平铺会让页面变成无尽长卷，读者失去导航感。这是综述最常见的退化模式。

**递归深度控制**：综述中被重点分析的论文（通常占 1 段以上篇幅）做深度展开；仅一两句带过的论文只需一句话定位 + 原文链接，不递归。判断标准：**综述作者花了多少篇幅讲它。**

**论文间关系**：每个子问题开头先讲一讲这一块的论文之间的关系，捋清楚脉络。

### 5. 跨方法对比

两篇都被提到的论文，方法相似或有明显承接关系的，采用 quote 的形式比较关键区别。**切忌过长过细的对比。**

### 6. 趋势与开放问题（轻量）

用 1 段总结综述的结论——领域往哪走、还有什么没解决、作者的观点。

## 页面组织

```text
核心结论（这篇综述覆盖什么领域、梳理了多少篇工作、核心结论）
  ↓
分类全景图 / Taxonomy（树或 mindmap，可交互导航）
  ↓
分支 A：概述 → 问题解耦 → 论文 A1（深度卡片）→ 论文 A2 → …
分支 B：概述 → 问题解耦 → 论文 B1 → 论文 B2 → …
  ↓
趋势 / 开放问题
```

- 顶部放一个**分类导航**（sticky sidebar 或 tab bar），让读者按兴趣跳到对应分支，不必线性通读
- 每个分支内部仍保持线性阅读顺序（概述 → 各论文 → 小结）
- 深度卡片默认折叠，读者按需展开——综述引用量大，全部展开会淹没读者

> **工作量提示**：综述覆盖 >15 篇重点论文时，在第 2 步定契约阶段主动与用户确认：是全部展开，还是只深入用户最关心的几个分支。

## Sub-Agent 并行调研（涉及 ≥3 篇需深度展开的论文时必做）

每篇论文的深度调研（获取结构、读方法 section、提取并验证图片 URL、整理示例）耗时较长，串行执行会严重拖慢整体速度。**必须启动 sub-agent 并行调研，而不是在主流程中逐篇串行获取。**

**执行方式**：

1. 为每篇需要深度展开的论文启动一个 `general-purpose` sub-agent（`run_in_background: true`）
2. 等所有 sub-agent 返回后，用收集到的素材统一构建 HTML
3. 某篇论文的 arXiv HTML 图片不可用时，sub-agent 应明确说明并建议自制图的内容描述

**每个 sub-agent 的 prompt 必须包含的调研任务**：

- 拉 `https://arxiv.org/html/<id>v<ver>/` 获取论文全文结构，定位 method section
- 从同一页面提取所有图片 URL 并逐个 `curl -sI` 验证 HTTP 200 且 `content-type` 为 `image/*`
- （本机装了 `deepxiv` 时可代替上面两步：`deepxiv paper <id> --head` 取结构，`deepxiv paper <id> --section <method_section>` 取方法详情。**没装就走 arXiv HTML 抓取，不要假设它存在**）

**每个 sub-agent 必须返回的结构化信息**：

```text
## 论文标题 + venue + 年份
### 核心方法讲解（3–6 段）
- 解决什么问题（动机）
- 核心做法：输入 → 处理 → 输出
- 关键设计选择和为什么
- 与前序工作的区别
### 已验证图片
- [URL] 描述：xxx（HTTP 200 已确认）
- 每张图的详细内容描述（图中每个模块、箭头、数据流）
### 具体示例
- 原文给出的 input-output 样例 / case study
### 关键数据
- 最重要的 2–3 个实验数字
### 局限性
```

> **严禁**：跳过 sub-agent 直接写 HTML，然后每篇论文只给两行介绍。如果你发现自己在为一篇论文写少于 3 段方法讲解且没有配图，**停下来——你缺少素材，需要先调研**。

## 递归取图策略

综述引用的每篇关键论文都需要配图：

1. 提取论文的 arXiv ID（或其他可定位的标识）
2. 从 arXiv HTML 版（`https://arxiv.org/html/<id>v<ver>/`）提取图片 URL，用 `curl -sI` 验证 HTTP 200（详见 @references/ingest.md 的取图规范，**注意禁用 ar5iv**）
3. 取到图后嵌入对应论文的深度卡片内
4. arXiv HTML 不可用时检查 GitHub 仓库；所有途径都失败时，根据综述中的文字描述自制 CSS/SVG 示意图
